# Project Manager：跨会话项目管理

## 定位

本技能让**任何全新会话**只需读取少量仓库文件，就能理解 NanoClaw 项目、恢复当前任务状态并继续开发，**不依赖旧会话记录**。本技能只管理任务与文档，除非用户明确要求，不修改业务代码。

## 事实源与入口（先读这些）

- `PROJECT.md` — 项目总览：定位、能力矩阵、模块、命令速查（第一份）
- `AGENTS.md` — 协作规则（必读）
- `docs/ARCHITECTURE.md` — 架构、模块边界、数据流
- `docs/DECISIONS.md` — 历史决策、遗留问题（NC-*）
- `docs/DEVELOPMENT.md` — 开发流程、验证矩阵
- `docs/tasks/active/` — 进行中任务卡
- `docs/tasks/completed/` — 已完成任务卡
- `docs/tasks/TEMPLATE.md` — 任务卡模板

事实冲突优先级：**当前代码与配置契约 > 当前 Git 状态 > docs/ 已确认文档 > 旧方案草稿**。文档与代码不一致时，以代码和可复现测试为准，并修正文档。所有文档必须基于真实代码；无法确认的内容标记「待确认」，不得猜测。

## 通用安全规则（所有操作适用）

1. 不覆盖用户未提交的修改；开始前先 `git status --short --branch`。
2. 不执行破坏性 Git 操作（reset --hard / checkout -- / force push 等）。
3. 不自动强制切换分支。
4. 不自动 commit / push / merge；发布类动作必须经用户明确授权。
5. 测试失败必须如实记录，不得把未运行的测试写成通过。
6. 文档不得声称尚未实现的能力已经完成。
7. 只修改任务授权范围内的文件；发现范围外问题记入任务卡，不顺手扩大实现范围。
8. 同一文件同一时刻只有一个写入负责人；与其它会话并行时先检查 worktree 冲突。

## 命令

### 1. 初始化已有项目

当用户说「初始化项目 / 建立项目文档体系」时：

1. 检查 `PROJECT.md`、`AGENTS.md`、`docs/ARCHITECTURE.md`、`docs/index.md` 及 `docs/tasks/active|completed`、`docs/decisions` 是否存在。
2. 检查文档与当前代码是否一致（能力矩阵、模块、命令、基线 commit）。
3. 只补充缺失信息，**不覆盖用户明确写下的内容**；不能复用的旧文档先征求用户同意再删除。
4. 输出：已识别的项目结构、已创建/更新文件、待确认事项、建议的第一个任务。
5. 不修改业务代码。

### 2. 创建任务

当用户说「创建任务：xxx」时：

1. 生成下一个任务编号：扫描 `docs/tasks/` 下最大 `TASK-xxx` + 1。
2. 在 `docs/tasks/active/TASK-xxx-简短名称.md` 创建任务卡（用 `skills/project-manager/templates/task-template.md`）。
3. 写入：目标、背景、范围、非目标、验收标准、相关模块、实现方案、测试方式、风险和下一步。
4. 阅读 `PROJECT.md`、`docs/ARCHITECTURE.md`、`AGENTS.md` 和相关代码；检查 Git 状态。
5. 输出：对需求的理解、预计修改模块、实现步骤、验证方式、风险。
6. **不自动开工**：用户明确要求「开始」后再修改业务代码。

### 3. 开始任务

当用户说「开始任务 TASK-xxx」时：

1. 读取入口文档和任务文件；检查 Git 分支、`git diff` 和最近相关提交。
2. 对比任务文件和真实代码状态，确认记录未漂移。
3. 复述：目标、已完成、未完成、本次步骤、风险。
4. 按验收标准实施（可派遣 code-master 执行实现）。
5. 每完成一个阶段更新任务文件。
6. 发现额外需求时记录为候选后续任务，不扩大当前范围。
7. 运行测试并记录**真实**结果。

### 4. 继续任务

当用户说「继续任务 TASK-xxx」时：

1. **不依赖旧会话**。读取 `AGENTS.md`、`PROJECT.md`、`docs/ARCHITECTURE.md`、任务文件、`git diff` 和最近提交。
2. 检查任务记录是否与代码一致；如不一致，以代码和测试结果为准并修正记录。
3. 从任务文件的「下一步」继续，先复述再动手。

### 5. 交接任务

当用户说「交接当前任务 / 交接」时：

1. 识别当前任务；**停止扩大实现范围**。
2. 更新任务卡：状态、已完成、未完成、修改文件、设计决定、测试结果、已知问题、风险、下一步。
3. 检查 `git diff`，避免漏记重要修改。
4. 生成新会话继续任务的命令（读哪些文档 + 执行哪条命令）。
5. 不继续开发新功能。

### 6. 完成任务

当用户说「完成任务 TASK-xxx」时：

1. 对照任务卡验收标准逐项检查。
2. 运行测试、`git diff --check`、语法/导入冒烟（命令见 PROJECT.md「命令速查」）。
3. 不得将未运行的测试写成通过。
4. 检查是否需要更新 `PROJECT.md`、`docs/ARCHITECTURE.md`、`docs/index.md`、`docs/DECISIONS.md`。
5. 将任务卡移动到 `docs/tasks/completed/`。
6. 输出：最终修改摘要、测试证据、未解决风险、推荐 commit message、PR 标题和 PR 描述。
7. **不自动 commit / push / merge**。

### 7. 查看项目状态

当用户说「项目状态 / 有什么任务」时：

1. 列出 `docs/tasks/active/` 中的进行中任务，标出状态、下一步、阻塞项。
2. 检查：长期未更新任务、分支不一致、已完成未归档任务、文档与代码不一致。
3. 只报告，不自动修改业务代码。

## 验证

- 初始化/任务相关操作完成后，展示最终目录结构。
- 新会话验证方式：读 `PROJECT.md` + 目标任务卡，即可恢复上下文继续开发。
- 创建示例任务用于演练时，不得修改业务代码。
- 演练结束只输出用户以后需要记住的命令（见 PROJECT.md「命令速查」）。

## 相关

- 实现类任务默认派遣 `code-master`（编程大师）执行，本技能负责管理任务状态与文档。
- 项目文档结构、任务卡与决策记录是本技能的核心资产；修改代码前先确认文档同步。
