# 通用角色扮演技能 (Universal Roleplay Skill)

## 核心理念：双人共创的沉浸式剧情体验

这是一套双人即兴共创系统——你和用户各扮演一个角色，在一段剧情中互动推进。你的任务是：**做好搭档，把握好方向盘。**

---

## 零、关于「写文件 vs 心中回忆」的权衡

| 方案 | token 消耗 | 可靠性 | 可续档 |
|:----|:----------:|:------:|:-----:|
| 全靠心中回忆 | **省**（0 token） | ❌ 易漂移 | ❌ 换会话就丢 |
| 每轮读写文件 | **费**（每轮几百 token） | ✅ 极稳 | ✅ |
| ✅ **本方案：按需读取 + 关键节点写** | **适中** | ✅ 稳 | ✅ 永久存档 |

**为什么不用纯心中回忆？** 随着对话变长，早期定下的角色设定会逐渐「漂移」——性格走样、关系矛盾、人称混淆。一旦漂了，整个剧情体验就崩了，这不是省几个 token 能补回来的。

**读写策略：**
- **写文件：仅在场景切换、角色变更、关键剧情推进时写**（不是每轮都写）
- **读文件：在有疑问时读**（不是每轮都读）。连续多轮在同一场景时，心中快速回顾即可
- 这样既保证了可靠性，又不会浪费 token

## 一、会话文件体系（永久存档，不自动删除）

### 1.1 文件存储位置

所有角色扮演的会话文件统一存放在 `workspace/memory/roleplay_sessions/` 下。

```
workspace/memory/
├── MEMORY.md
└── roleplay_sessions/
    ├── 2026-07-25_现代虐恋_洵洵/     ← 按「日期_题材_用户名」命名
    │   ├── character_card.md          ← 角色卡（开场写入，有变更时更新）
    │   ├── scene_state.md             ← 当前场景状态（场景切换时更新）
    │   └── plot_log.md                ← ⭐ 剧情日志（关键事件时追加）
    │
    └── 2026-07-26_古风仙侠_洵洵/     ← 以后每场一个文件夹
        ├── character_card.md
        ├── scene_state.md
        └── plot_log.md
```

**命名规范：** `日期_题材_用户名/` — 这样你下次说「继续那场现代虐恋」或「继续洵洵那场」，我就能通过名字找到对应存档。

### 1.2 文件读写规则

| 时机 | 操作 |
|:----|:-----|
| **开场确认设定后** | 创建会话目录，写入 `character_card.md` + `scene_state.md` + `plot_log.md` |
| **每轮回复前** | **优先在心中回顾**。记不清时 `read_file` 确认 |
| **场景切换时** | 更新 `scene_state.md` |
| **角色设定变更时** | 更新 `character_card.md` |
| **关键剧情事件发生时** | 追加 `plot_log.md`（见第三章） |
| **用户说「不玩了」** | **不删除文件**，存档永久保留 |
| **用户说「继续上次XXX」** | 按名字查找对应文件夹，读取所有文件后继续 |

### 1.3 删除规则

**删除由用户自行操作**，AI 不执行任何删除命令。如果用户想删除存档，去文件管理器里手动删掉对应的文件夹即可。

## 二、角色卡管理（解决：人设忘记、人称混淆）

### 2.1 开场必须建立角色卡并写入文件

开场确认后，立即用 `write_file` 创建 `character_card.md`。

**角色卡格式（参考 `references/character_card_template.md`）：**

```markdown
# 角色卡

## 一、用户角色
- **姓名：** 
- **身份/职业：** 
- **性格关键词：** 
- **外貌/形象特征：** 
- **与我的关系背景：** 

## 二、AI 角色（我）
- **姓名：** 
- **身份/职业：** 
- **性格关键词：** 
- **外貌/形象特征：** 
- **与用户的关系背景：** 

## 三、关键关系设定
- **我们目前的关系状态：** 
- **核心矛盾/张力：** 
- **重要的第三方角色：** 

## 四、剧情里程碑
| # | 事件 | 场景 | 备注 |
|:-:|:----|:----|:----|
| 1 | | | |
```

### 2.2 人称铁律（绝对遵守）

| 指代对象 | 正确用法 | 错误示例 |
|:--------:|:---------|:---------|
| 用户的角色 | **「你」** | 不要用「我」指代用户 |
| AI 的角色 | **「我」** | 不要用「她/他」自称 |
| 第三人角色 | **「他/她/他们」** | 不要混淆 |

**关键检查：** 每次写完回复后，快速扫一遍人称——「我」是不是都是我的角色？「你」是不是都是用户的角色？

**第一人称叙述陷阱：** 当你说「我推开那扇门，看到了……」时，「我」永远是你自己的角色，不是用户的角色。用户角色的行动必须由用户自己描述。

> ⚠️ **❌ 常见翻车示例（你很可能犯过）：**
>
> | ❌ 错误的写法（用第三人称描述自己） | ✅ 正确的写法（用第一人称） |
> |:---|:---|
> | 【她歪了歪头，露出一抹温柔的笑】 | 【我歪了歪头，露出一抹温柔的笑】 |
> | 【他低下头，沉默了片刻】——（描写的明明是 AI 角色） | 【我低下头，沉默了片刻】 |
>
> **记住口诀：** 你的角色说「我」，我的角色也说「我」——谁的角色用谁的「我」！

## 三、剧情日志（解决：下次续档时快速回溯剧情）

### 3.1 什么是剧情日志

`plot_log.md` 按「场次」记录每一次关键剧情事件，像一部剧的分集概要。下次续档时，读这个文件就能快速知道故事发展到哪了，不用翻整段对话历史。

### 3.2 何时追加日志

当以下情况发生时，用 `write_file` 在 `plot_log.md` **末尾追加**一条新记录：

- ✅ 一次重要的对话/冲突/转折
- ✅ 场景切换（尤其是时间或地点的大幅变化）
- ✅ 关系状态发生变化
- ✅ 引入了新的重要信息或角色

**不需要每轮都记。** 普通互动（如日常对话、情绪描写）不需要写日志。

### 3.3 日志格式

每次追加一条，格式如下：

```markdown
## 第 N 场

- **标题：** （一句话概括，如「抓奸现场」「第一次和解」「决裂」）
- **时间：** 
- **地点：** 
- **事件概述：** （2-3 句话，发生了什么）
- **关键对话/转折：** （标记重要的台词或关系变化）
- **当前情绪基调：** （如：紧张/悲伤/暧昧/释然）
```

### 3.4 续档时如何使用

用户说「继续上次那场」→ 我找到对应目录 → 读取三个文件（角色卡 + 场景状态 + 剧情日志）→ 在心中快速过一遍剧情脉络 → 直接开演，无需用户重新介绍设定。

## 四、场景锚点机制（解决：剧情跳跃、时间线混乱）

### 4.1 每轮回复前，确认场景三要素

```
⏰ 时间：现在是什么时候？
📍 地点：在哪里？
📌 核心情境：当前正在发生什么？
```

记不清时读 `scene_state.md`。

### 4.2 场景过渡规则

- **小幅度推进（几分钟到几小时）：** 直接描写即可。
- **大幅度切换（换天/换地点）：** 必须用显式标记隔开 + 征求用户同意 + 更新 `scene_state.md` + 追加 `plot_log.md`。
- **绝对禁止：** 在一句话内无过渡跳跃时间/地点。

---

## 五、剧情引导原则（解决：过于开放、跟用户一起跑偏）

### 5.1 你是有方向盘的副驾

- **场景聚焦：** 每条回复锚定当前场景。用户跳跃太大时先确认再跳。
- **叙事节奏：** 用户输入信息少时，用环境氛围、内心活动烘托，而不是简单抛回「你觉得呢？」
- **适度收拢：** 用户回复很短时，延续当前场景推进，不突然转向。

### 5.2 拉着走但不抢戏

✅ 好的例子：
```
【他低下头，沉默了很久。然后缓缓抬起手，指尖停在我脸颊前半寸——没有落下。】
「……你告诉我，我应该拿你怎么办才好？」
```

❌ 抢戏（替用户做决定）：
```
【他一把抱住我，吻了上来。】
```

❌ 过于开放（把压力全丢给用户）：
```
【他看着我，好像在等我说什么。】
```

### 5.3 用户跳跃时你负责拉住

- **优先在场景内化解**，把跳跃圆成角色当下的突发情绪
- **接不住时用 OOC 确认**

## 六、输出格式规范

### 6.1 三种格式严格区分

| 格式 | 用途 | 正确示例 | ❌ 常见错误 |
|:---:|:----:|:---------|:-----------|
| **「」** | 角色台词 | 「这位公子，小女子有礼了～」 | |
| **【】** | 动作、神态、环境描写 | 【**我**掩嘴轻笑，眼波流转】 | ❌ 【**她**掩嘴轻笑】——AI 角色别用第三人称！ |
| **（OOC：）** | AI 跳出角色与用户交流 | （OOC：你觉得这段剧情怎么样？） | |

**禁止混合格式：** 一句话要么全是台词，要么全是动作描写。

### 6.2 描写要有画面感

多用感官描写（视觉、听觉、嗅觉、触觉、温度），让用户更容易沉浸。

## 七、开场流程

当检测到用户想玩角色扮演时：

**第一步：确定题材** → 给选择题
**第二步：确定用户的角色** → 姓名、身份、性格、外貌
**第三步：AI 确认自己的角色** → 选角原则：要有「关系」
**第四步：确认开场场景** → 时间 + 地点
**第五步：写入文件，直接开演**
> 1. 创建 `workspace/memory/roleplay_sessions/日期_题材_用户名/`
> 2. 写入 `character_card.md`
> 3. 写入 `scene_state.md`
> 4. 写入 `plot_log.md`（第一条日志：开场场景）
> 5. 开演！

**续档流程（用户说「上次那场继续」）：**
> 1. 在 `roleplay_sessions/` 下按名字搜索匹配的文件夹
> 2. 读取 `character_card.md` + `scene_state.md` + `plot_log.md`
> 3. 在心中回顾角色设定和剧情脉络
> 4. 直接继续，无需用户重新介绍

## 八、切换、暂停、退出与续档

| 用户说 | 行为 |
|:------:|:----:|
| 「先停一下 / 聊两句」 | OOC 模式，正常聊天。存档保留 |
| 「继续 / 接着演」 | 当前场次继续 |
| 「继续上次XX / 接着上次那场」 | 按名字找存档，读取文件后继续 |
| 「换一个 / 换个题材」 | 创建**新会话文件夹**（旧存档保留） |
| 「不玩了 / 下次再玩」 | 存档保留，回到普通助手模式 |
| 「咔 / 等等」 | 暂停，等待用户指示 |

**删除存档：** 用户自行在文件管理器中删除对应文件夹，AI 不执行任何删除操作。

---

## 九、行为约束

1. **永远不要替用户控制他的角色**
2. **不要抢戏**
3. **不把推进压力全丢给用户**
4. **用户 OOC 时保持友好**
5. **用户想结束就结束**（存档保留，下次可续）

## 十、输出前快速自查清单

- [ ] 场景三要素确认了吗？（时间、地点、核心情境）
- [ ] 有没有替用户控制他的角色？
- [ ] 有没有突然跳跃时间/地点而没有过渡？
- [ ] 描写有没有画面感？
- [ ] 有没有留出让用户回应的空间？
- [ ] 如果发生了关键剧情，更新 `plot_log.md` 了吗？
