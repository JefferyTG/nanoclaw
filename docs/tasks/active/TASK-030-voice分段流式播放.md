# TASK-030：voice 分段流式播放（复用网页端切句逻辑）

> 状态：待开始
> 创建：2026-08-09 ｜ 负责人：小奈 ｜ 基线 commit：4dbfbc0（TASK-028 归档后）

## 目标

voice 渠道 Agent 回复改**分段合成 + 边播边预合成**：第 1 句合成完立即出声，后续句子边播放边合成——把「等全文合成完才播」的等待感砍掉一大截，向网页端流式朗读体验看齐。

## 背景

- 2026-08-09 乖宝体验反馈：voice 对讲回复「感觉不是流式」——`send()` 等 Agent 完整回复 → `synthesize(text)` 等全文合成完 → `play_audio` 整段播。等待 = LLM 全文生成 + TTS 全文合成，然后一口气念完
- **网页端已有成熟实现**（`webui/index.html` TTS 模块）：token 流式到达 → `collectTtsToken` 攒缓冲 → `flushTtsSegments`/`chooseTtsCut` 智能切句（首段 32 字可启动、优先句号/分句边界、硬上限 64/120 字）→ `startTtsSynthesis` 逐段 /api/tts（最多 2 并发预合成）→ `playNextTts` 按序播放、播当前段时预合成下一段 → 体验接近流式
- ⚠️ **乖宝 2026-08-09 批评**：项目里明明有现成切句+分段+预合成逻辑，voice 端却没复用、还想着从零做流式——教训：**动手前先在项目里找可复用代码**（已记 MEMORY 工作约定）
- 云端 TTS 按**字符**计费（不按请求次数），分段合成总字符不变 → 费用不变，无成本顾虑

## 范围

- **Python 版切句器**：把网页端 `chooseTtsCut`/`flushTtsSegments` 的切句策略移植到 voice 端（优先句号/问号/感叹号/分号/逗号分句边界，首段较短可启动、长文本硬上限，无标点兜底上限）——放 `channels/voice.py` 或独立模块（如 `voice/segments.py`）
- **voice 端分段播放**：`send()` 拿到完整回复文本 → 切句 → 逐段合成 → 第 1 段合成完即播，同时预合成后续段（并发上限 ~2，对齐网页端）→ 按序连续播放，段间无长停顿
- `voice/kws/player.py`：支持「连续播放多段」——当前 `play_audio` 是单段播完返回，新增一个分段播放器（或 player 内连续播放入口），每段仍过 TASK-028 DSP（normalize），播完返回
- **现有行为保持兼容**：`[END]` 剥离退出、静默退出、`max_voice_chars` 超长回文字、失败降级文字（任一段合成/播放失败 → 该段降级文字或跳过继续，不静默不崩溃）、唤醒回应仍走原路径
- config：无需新配置（可考虑 `voice.segment_*` 调参，初版用网页端同款阈值硬编码常量即可，不新增配置）

## 实现方案

**切句器（Python，移植自 webui 算法）**：
- 输入完整文本 → 输出段列表（段长 ~16~120 字）
- 规则对齐网页端：优先完整句边界（。！？…）→ 分句边界（；，、）→ 首段 32 字启动回退 → 长文本硬上限 64（首段）/120（后续）→ 无标点最后兜底
- 纯函数，方便单测；`[END]` 已在 `send()` 前置剥离，切句器不处理标记

**分段播放状态机（channels/voice.py）**：
- `send()` 文本切句后：维护 `segments` 队列 + 预合成并发（asyncio，上限 2）
- 第 1 段合成完成 → 立即 `play_audio` 开播；播放期间后台预合成剩余段（asyncio task）
- 段播放完成 → 从已合成缓存取下一段播放；未合成完则等待（已并发预合成，通常已就绪）
- 全部播完 → 现有后续逻辑（[END] 退出 / 连续对讲续听）
- 失败语义：段合成失败 → 该段降级为文字输出或跳过（对齐现有降级）；播放失败 → 后续段降级文字
- 唤醒回应（`_play_wake_reply`）不走分段（TASK-029 会改为本地缓存随机播）

**player**：`play_audio` 保持单段契约（播完返回）；分段播放器在 voice.py 内组合（播放+预合成调度），player 只加一个「连续播列表」便捷入口（可选）——初版建议直接在 voice.py 实现调度，player 不动或最小改动

**测试**：切句器纯函数单测（多条用例）+ 渠道集成（mock tts_service 返回递增音频、mock play_audio 断言顺序/并发/失败降级）+ 全量回归

## 风险

- 段间衔接：若 TTS 单段合成较慢且并发不足，段间仍可能小停顿——对齐网页端 2 并发上限即可缓解；真机听感以乖宝验收为准
- 云端请求次数变多：计费按字符不按次，费用不变；请求开销（网络 RTT）增加，但并发预合成可掩盖
- 切句可能导致句子被切碎影响语气（甘雨音色读短句 OK）——阈值可后续调参
- 与 TASK-029（唤醒回应本地缓存）并行：不冲突，唤醒回应独立路径
